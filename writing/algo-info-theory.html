How do you quantify the amount of information in a distribution? There are two classical attempts: random information, as quantified by Shannon's information theory, and structural information, as quantified by Kolmogorov's complexity theory. For example, the uniform distribution has high entropy (i.e. high random information) and low Kolmogorov complexity (i.e. low structural information). In this post, we will connect both perspectives under Algorithmic Information Theory and discuss their merits/pitfalls. The introductory material in this post closely follows exposition from Li and Vitanyi, 2008, Aaronson et al, 2014, and Finzi et al, 2026 and is intended to provide exposition for our treatment of epiplexity (Finzi et al, 2026) in Interestingness Part 2 (TODO).


Information theory

Entropy

Given a probability distribution $P$ over bitstrings $x$, the (Shannon) entropy is defined as

$$H(P) = \Eof{x\sim P}{-\log P(x)}$$

The entropy quantifies randomness and prediction difficulty inherent to a distribution. For example, the lowest cross-entropy error a generative model can achieve is the entropy of the ground-truth distribution (cross-entropy $H(P,Q)$ is $\KL{P}{Q} + H(P)$, and KL is non-negative).

Compression

Suppose our goal was to compress bitstrings from the distribution by mapping them to a unique bitstring (a motivating example is to communicate these bits across a channel). When constructing such a uniquely decodable code, we would presumably assign shorter bitstrings to the frequent samples. Shannon's source coding theorem states that the expected codelength of any such code is lower-bounded by the entropy. Furthermore, there exists a code $f$ such that the expected codelength is upper-bounded by the entropy plus one. Furthermore, the optimal encoding $f$ satisfies

$$H(P) \leq \Eof{x\sim P}{|f(x)|} \leq H(P) + 1$$

Complexity

Sample level complexity

The Kolmogorov complexity of a string $x$ is the length of the shortest program under a fixed Turing machine that produces the string, denoted $K(x)$.


One might be concerned that the specific implementation of the Turing machine may affect the Kolmogorov complexity. Interestingly, choosing between universal Turing machines $T_1$ and $T_2$ only affects the Kolmogorov complexity up to a constant that depends on $T_1, T_2$. This is because it is possible to implement a transpiler that translates programs from $T_1$ into $T_2$. Therefore, if there was a substantially shorter program in $T_1$, one could simulate it in $T_2$ after implementing the transpiler in constant bits. Going forward, we will always operate under an arbitrary such Turing machine $U$.

Kolmogorov at sample level is effectively entropy

The previous subsection defines Kolmogorov complexity at the distribution level. It is important that we do not apply this definition to the sample level since the expected complexity of a random string is close to the entropy of the generating distribution. More formally, for distribution $P$ we have that

$$H(P) \leq \Eof{x\sim P}{K(x)} \leq H(P) + K(P) + O(1)$$

For the lower bound, note that the code given by the shortest program witnessing each Kolmogorov complexity would contradict the entropy lower bound from Shannon's source coding theorem. For the upper bound, note that one possible way to encode $x$ is to first encode the probability distribution and then encode $x$ as a sample of the distribution. This gives $K(x) \leq K(P) - \log P(x) + O(1)$. Taking the expectation of both sides over $x \sim P$ gives the bound.

Complexity for samples? (sophistication)

The above analysis reveals that Kolmogorov complexity fails to quantify complexity at a sample level; for example, the uniform distribution has high entropy and thus high expected per sample complexity but the uniform distribution does not intuitively have structural complexity. There have been many attempts to satisfyingly quantify complexity for samples, the most representative attempt being (coarsened) (naive) sophistication. Model selection via minimum description length

So far, we have kept the notions of structural and random information completely seperate of each other. However, when selecting models according to data (i.e. learning), we are interested in balancing both. This classical idea of Occam's razor (selecting the simplest hypothesis that explains the data) is formalized under the Minimum Description Length principle for two-part codes. More formally, for data $x$ and candidate programs $\mathcal{H}$, the minimum description length is

$$L(x) = \min_{h\in\mathcal{H}} |h| - \Eof{x\sim P}{\log P_h(x)}$$

We can further decompose the MDL into its structural component (the value of $|h|$ at the minimizer) and random component (the negative log likelihood at the minimizer). This would be equivalent to Kolmogorov complexity if we dropped the right term and entropy if we dropped the left term. This subtle difference will become much more relevant when we introduce computational constraints in Part 2.

Conclusion

Hopefully the above posts offers a simple theoretical framework for quantifying structural and random information. However, such notions still feels inadequate: pseudo-random number generators should intuitively have high random information, and math should intuitively have high structural information, but our current notions would give low structural and random information to both. Appendix A: Sophistication

To separate the random information from the structural information within a string, naive sophistication aims to quantify the complexity of defining a typical set. For a sample $x$, a typical set $S$ satisifies $K(x \given S) \geq \log |S| - c$ (the shortest description of $x$ is as a random element of $S$ up t a constant threshold $c$). Naive c-sophistication ($\text{nsoph}_c(x)$) is the minimum of $K(S)$ over all typical sets for $x$ TODO CITE. To remove the sensitivity to $c$, we can take coarsened naive c-sophistication as $\text{cnsoph}_c(x) = \min_c \{c + \text{nsoph}_c(x)\}$. The naive sophistication is at worst $K(x) + O(1)$ which can is witnessed by $S = \{x\}$. We have already shown that most strings have high Kolmogorov complexity; such strings are low sophistication because we can take $S$ to be the set of all bit strings.


Naive sophistication actually comes from the more classical notion of sophistication ($\text{soph}_c(x)$) which adds the additional constraint that $S$ must give a near-optimal encoding of $x$, or $K(S) + \log_2|S| - c \leq K(x)$. We refer to this as a two-part code since we are encoding $x$ via $S$, and in the next section we will see a distribution level two-part code. Since $K(x) \leq K(x\given S) + K(S)$, the optimality of the two-part code $S$ implies that $S$ is a typical set. Interestingly, sophistication and naive sophistication (coarse or not coarse) are known to be quite close TODO CITE.

$$\text{nsoph}_{c}(x) \leq \text{soph}_{c+O(\log n)}(x) \leq \text{nsoph}_{c}(x)$$ $$\text{ncsoph}(x) \leq \text{csoph}(x) \leq \text{ncsoph}(x) + O(\log n)$$

Knowing that all these metrics are equivalent, does naive sophistication capture what we're looking for? Unfortunately, it is quite a sad story. The only existence proof of sophisticated strings uses a non-constructive diagonalization argument. Even optimizing for sophistication seems like a lost hope since it is bi-level over $x$ and $S$.
